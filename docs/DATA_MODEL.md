# Safe Path: data model

The models follow the ERD in the graduation report (`التوثيق النهائي.pdf`, section 3.10; transcribed in `../SafePath-ERD.md`), with the critical problems found in it fixed. This file records where the code differs from the ERD and why.

## Apps

| App | Models | ERD entities |
|---|---|---|
| `core` | `ModelWithTimeStamp`, `UUIDModel` (abstract), `ReadOnlyAdminMixin` | – |
| `accounts` | `User`, `Parent`, `Student`, `Institution` | user, parent, student, EducationalInstitution |
| `groups` | `Group`, `GroupMembership`, `GroupPermission`, `MembershipPermission` | GROUP, STUDENT_GROUP, permission, mempershippermission |
| `trips` | `Trip`, `TripStudent`, `ActiveTrip`, `LocationPoint`, `TripEvent` | TRIP, trip_student, ActiveTrip, locaionHistory, TripEvent |
| `geofences` | `Geofence`, `InstitutionGeofence`, `TripGeofence`, `GeofenceEvent` | GEOFENCE, institution_geofence, trip_geofence, geofence_event |
| `safety` | `EmergencyContact`, `SOSAlert` | emergencyContact, SOS_ALERT |
| `notifications` | `Notification` | Notification |
| `reports` | `Report` | report |

App dependencies run one way only: `accounts` ← `groups` ← `trips` ← `geofences` / `safety` ← `notifications`, and `reports` uses `accounts` and `groups`.

## Conventions (same as the clinic project)

- Primary keys are UUIDs. Every table has `created_at` and `updated_at`, except `LocationPoint`, which has `received_at` only because it is high volume and never updated.
- Choices are `TextChoices`, and each one is also enforced by a database `CHECK` constraint.
- Rules that hold for every row are database constraints, not only Python validation.
- Locations are PostGIS `PointField`s (SRID 4326, longitude first), not separate latitude and longitude columns.
- Foreign keys use `PROTECT`, so history can't be deleted by accident. The exceptions are pure link rows (`MembershipPermission` cascades with its membership) and optional links to a user (`SET_NULL`).

## Fixes made to the ERD

| # | ERD problem | What the code does |
|---|---|---|
| 1 | `TRIP` to `ActiveTrip` was 1 : 1, so a trip could only be run once | `ActiveTrip.trip` is a normal foreign key, so a trip has many runs. Only one run per student can be in progress at a time. |
| 2 | `emergencyContact` had no owner, and it and `SOS_ALERT` pointed at each other | `EmergencyContact.student` added, `sos_id` removed. One active primary contact per student. |
| 3 | The SOS location pointed at a synced GPS row | `SOSAlert.point` stores the location directly, because an SMS alert sent offline may have no synced point. |
| 4 | Offline sync could store the same row twice | `LocationPoint`, `TripEvent`, `GeofenceEvent` and `SOSAlert` accept an id generated by the phone. Re-sending a known id is skipped (`bulk_create(..., ignore_conflicts=True)`). The phone's own time (`recorded_at` / `occurred_at` / `triggered_at`) is stored separately from when the server received the row. |
| 5 | No place for the expected route or the time a student must stay inside the destination before it counts as arrival | `Trip.start_point`, `destination_point`, `expected_route` (line) and `expected_duration`; `Geofence.dwell_seconds`; `TripGeofence.purpose` with one destination per trip. |
| 6 | School entry and exit needed an active trip | `GeofenceEvent.active_trip` is optional. **Still to decide:** whether the app records crossings outside trips. |
| 7 | A group could have both a parent and an institution as owner | `CHECK` constraint: exactly one of `Group.parent` and `Group.institution`. |
| 8 | Notification had three nullable source keys and no rule | `notification_type` decides which source is filled: trip → `trip_event`, geofence → `geofence_event`, sos → `sos_alert`, others → none. Enforced by a `CHECK` constraint. |
| 9 | Reports had no subject | `Report.student` and/or `Report.group`, at least one required. One report per recipient, subject and period. |
| 10 | Invite codes never expired and memberships had no states | `Group.invite_code` (random, unique) with `invite_code_expires_at`. Membership statuses: pending, active, rejected, left, removed, with the matching timestamps enforced. |
| 11 | Link tables had no key | Unique constraints on `TripStudent`, `InstitutionGeofence`, `TripGeofence` and `MembershipPermission`. |
| 12 | `passwrd` stored as a column | Django's hashed password. Login by phone number; email is unique ignoring case so it can be a second login. |
| – | `user.status` | `is_active`, as in Django and the clinic project. |
| – | `GROUP.group_type` | Dropped: the owner already says whether it's a family or an institution group (`Group.owner`). |
| – | `locaionHistory.sync_status` | `LocationPoint.recorded_offline`: whether the point was stored on the phone and synced later. |
| – | ERD spelling | Names corrected (`institution`, `relationship`, `membership`, `alert`, …). |

## Admin

- **Editable:** data people set up (users, profiles, groups, memberships and their permissions, trips, geofences, emergency contacts) and the platform-managed permission list. These stay editable so test data can be entered before the APIs exist.
- **View-only** (`ReadOnlyAdminMixin`): data recorded by phones or the system (runs, locations, trip events, geofence events, SOS alerts, notifications, reports).
